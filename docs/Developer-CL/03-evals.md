# CL-03 — Eval harness, golden set, model selection (CL-M3)

**Goal:** measure (not guess) which model and prompt is good enough. Then switch on auto-apply (NFR-09).
**Uses:** CL-M2 agents. It does not need OA, because evals run in-process on the text files.

## 3.1 Layout
```
evals/
├─ docuhive_evals/            # importable package (added to the workspace via pyproject)
│  ├─ cli.py                  # `docuhive eval …` subcommands (registered via docuhive.ai.cli)
│  ├─ datasets.py             # loaders for the formats below
│  ├─ scorers.py              # per-field metrics
│  └─ report.py               # markdown + JSON writer, comparison tables
├─ synthetic/                 # committed, no real data
│  ├─ docs/<id>.txt           # document text (as OCR would produce)
│  ├─ labels.yaml             # expected classify + extract output
│  ├─ search.yaml             # queries -> expected doc ids
│  └─ qa.yaml                 # questions -> expected citations / numbers
├─ ocr/                       # OA-owned (CER script from OA-M1)
└─ reports/                   # gitignored
overlay/evals/golden/         # PRIVATE: same format as synthetic/, real documents
```

## 3.2 Dataset format
`labels.yaml`:
```yaml
- id: inv-001
  file: docs/inv-001.txt          # or a PDF in the golden set: text is extracted with OA's text.py
  expect:
    category: utilities/electricity
    document_type: invoice
    correspondent: "Stadtwerke Musterstadt"
    document_date: 2025-11-01
    language: de
    tags: []
    facts:
      amount_total: { value: "84.20", currency: EUR }
      due_date: "2025-11-20"
  restricted: false
```
- **Synthetic set:** 40 documents generated by `evals/synthetic/generate.py`, which is template-based and seeded. They are realistic texts in German and English for each document type, with noise (OCR typos, headers and footers, multi-page). The generator script is committed, along with its output.
- **Golden set:** about 100 real documents in the overlay. **Bootstrapping:**
  1. **Before the app exists:** label 30 documents by hand in the YAML above, using OA's spike sample set.
  2. **After CL-M2:** `docuhive eval export-golden --reviewed --n 100 --out overlay/evals/golden` exports documents whose fields were **all user-confirmed** (in `manual_fields`, or every review item accepted or edited). Each document gets a `labels.yaml` entry plus its text. Reviewed documents are the ground truth. Stratify by document type.

## 3.3 Metrics (`scorers.py`)
| Field | Metric |
|-------|--------|
| category | exact accuracy; also "parent accuracy" (`utilities/*` vs `utilities/electricity`) |
| document_type | exact accuracy |
| correspondent | normalised exact, plus fuzzy (trigram ≥ 0.75) accuracy |
| document_date | exact |
| language | exact |
| tags | micro precision, recall and F1 |
| facts | per fact: exact (money = same amount and currency; date exact; string normalised) plus coverage (non-null when expected) |
| validity | schema-valid rate (first try), retry rate, unknown-label rate |
| cost/speed | latency p50/p95, tokens in/out, USD per 100 documents (from `pricing`) |
| calibration | accuracy of the fields with confidence ≥ threshold (this is what auto-apply would do) and the share of fields above the threshold: **this is the gate metric** |

## 3.4 CLI
```
docuhive eval classify --set evals/synthetic [--set overlay/evals/golden] \
    --route classify=ollama/qwen3:8b --route classify=anthropic/claude-haiku-5-5 \
    [--prompt classify] [--limit 50] [--concurrency 2] [--out evals/reports/]
docuhive eval extract  --set … --route extract=…
docuhive eval search   --set … --mode hybrid|fts|semantic   # needs a DB with the set ingested
docuhive eval ask      --set … --route chat=…
docuhive eval export-golden --reviewed --n 100 --out overlay/evals/golden
```
- `--route` repeated → a side-by-side comparison table.
- The privacy gate **also applies in evals**: a document marked `restricted: true` is only run against local routes, and cloud runs report it as "skipped".
- The report is `evals/reports/<date>-<task>.md` and `.json`. Commit a summary of each golden-set report to `overlay/evals/reports/` (private), and synthetic-set reports may go in the public `docs/evals/`.

### Search and Ask evals (used in CL-M5 and CL-M6)
- **`search.yaml`:** `- {query: "Stromrechnung November", expect: [inv-001], k: 10}`. The command ingests the set into a throwaway DB (via OA's CLI when available, otherwise by inserting content directly with the fakes) and reports recall@10 and MRR per mode.
- **`qa.yaml`:**
  ```yaml
  - question: "How much did I pay for electricity in 2025?"
    expect_citations: [inv-001, inv-002]
    expect_number: { value: 1012.40, tolerance: 0.01 }
  ```
  Metrics: citation recall, number correctness, "answered without sources" rate.

## 3.5 CI — `.github/workflows/evals.yml` (CL)
- On PRs touching `agents/`, `prompts/`, `taxonomy/` or `evals/`, run the harness on the synthetic set with **FakeModel** as a smoke test (the machinery works and the metrics compute).
- Nightly (optional, self-hosted runner or manual dispatch): the synthetic set against Ollama `qwen3:4b` in a service container. Fail if category accuracy drops more than 5 points versus `docs/evals/baseline.json`.

## 3.6 Model selection & gate (decision record)
1. Run `classify` and `extract` on the golden set for at least two local models and one cloud model.
2. Write `docs/decisions/0004-model-selection.md`: the table, the chosen default routes, and the threshold.
3. **Gate to set `apply.auto: true`:** on the golden set, for fields above the threshold, accuracy is ≥ 95% (calibrated precision), **and** overall category and document type accuracy is ≥ 90% (NFR-09).
4. Put the chosen routes and thresholds in your overlay `routing.yaml`. Update the public defaults only if the synthetic results support it.
5. Re-run after any prompt change (the prompt version is in every report).

## 3.7 Tests
- Scorers: unit tests with hand-computed expectations.
- Dataset loader: schema validation errors are readable.
- A CLI smoke test with FakeModel on 5 synthetic documents.

## Acceptance
- `docuhive eval classify` produces a comparison report for at least two routes on the synthetic set in CI, and on the golden set locally.
- The decision record exists, and `apply.auto` is enabled in your overlay only if the gate passed.
