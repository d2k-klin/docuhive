# Document chat

Chat is how most people will *find* things: "where's my car insurance policy?", "what did I pay for heating last winter?", "when does my phone contract end?". It must feel obvious to a non-technical user, and every answer must be **checkable** (sources one click away, numbers computed rather than guessed).

## Entry points (make chat reachable everywhere)

| Where | How | Scope it starts with |
|-------|-----|----------------------|
| Top bar | an "Ask" button, plus the `⌘K` / `Ctrl+K` palette (type a question → Enter opens Ask) | whole archive |
| Document page | "Ask about this document" | `document_ids: [id]` |
| Documents list with filters | "Ask about these 37 documents" | the current filters |
| Search page, no good results | "Ask instead" with the query prefilled | whole archive |
| Dashboard | 3 suggested questions | whole archive |

## The Ask screen

- **Scope bar** (always visible, above the input):
  - chips for the active scope: category, type, date range, "This document"
  - each chip is removable, with a "+ Filter" button
  - a privacy badge: **Local** (green) or **Cloud: <provider>** (neutral). Hovering it explains it in one sentence.
  - a "Local only" switch
- **Input:**
  - a textarea that auto-grows up to 6 lines. Enter sends, Shift+Enter adds a newline.
  - the placeholder rotates real examples ("e.g. When does my car insurance renew?")
  - a Send button, which becomes **Stop** while streaming
- **Empty chat:**
  - 3–6 suggestion chips **built from the user's archive**: the top categories with document types that have facts. For example, invoices in `utilities/*` → "How much did I spend on electricity this year?"; contracts → "Which contracts can I cancel in the next 3 months?"
  - a one-line explanation of what chat can do

## An answer

1. **Streaming text** (markdown, sanitised), at a 65ch reading width.
2. **Inline citations** `[doc:ID]` rendered as compact chips "📄 Stadtwerke · Nov 2025". On hover or focus they show a preview card (thumbnail, title, date, category); a click opens the document in a side panel (desktop) or a new view (mobile), staying in the chat.
3. **Sources section** under each answer: the list of all documents used, plus "Open as list" (→ `/documents?ids=…`), and "Ask about only these".
4. **Numbers:** when `query_facts` ran, show a small table (date, document, amount) with **per-currency totals** and a note "Calculated from N documents". Amounts are right-aligned and tabular. Never show a total the tool didn't compute.
5. **"What I did"** (collapsed): "Searched for 'Strom 2025' · Read 3 documents · Calculated totals", with an "Under the hood" link to the run (learning-showcase skill).
6. **Follow-ups:** 2–3 suggested next questions as chips (generated by the agent in a structured trailer, validated, never containing ids).
7. **Feedback:** 👍 / 👎 with an optional reason ("wrong number", "missing document", "wrong document"). Stored on the message, and exported as candidate eval cases by `docuhive eval export-qa --feedback` (CL-03).

## When things go wrong (say what to do)

| Situation | What the user sees |
|-----------|--------------------|
| Nothing found | "I couldn't find documents about that." Then: "Try: broader dates · remove the category filter · check the spelling · [Upload the document]". Never an invented answer |
| Ambiguous | the agent asks **one** clarifying question with options as chips ("Which insurance? Car · Home · Health") |
| Restricted docs masked (cloud route) | "2 matching documents are private and weren't sent to <provider>. Switch to Local to include them." with a switch |
| Budget exceeded / provider down | "The cloud model isn't available right now." Buttons: [Use local model] [Retry] |
| Answer without sources | a yellow note: "This answer isn't based on your documents." |
| Stopped by the user | the partial answer is kept and marked "Stopped", with a Retry button |

## History & sessions

- A sidebar (a drawer on mobile) listing past chats. The title is auto-generated from the first question (≤ 6 words), and can be renamed or deleted. "New chat" sits at the top.
- Each chat remembers its scope, route and Local-only setting.
- A saved analysis is a chat question with a name: "Save as analysis" on any answer → `/analyses`.

## Agent behaviour (keep the prompt and tools aligned with the UI)

- Use `search_documents` first. Use `read_document` only for the top hits needed. Use `query_facts` for **any** number. Cap at 8 tool calls per turn.
- Cite every factual sentence. Answer in the question's language. Be brief by default (2–6 sentences + table), and give more only if asked.
- Prefer exact dates and amounts from facts, and state the period covered ("1 Jan–31 Dec 2025").
- The scope (filters, `document_ids`) is enforced by the tools, not by the prompt.

## Accessibility & keyboard

- The message list is `aria-live="polite"` for streamed text, and the Stop button is focusable while streaming.
- `⌘K` opens the palette. `/` focuses the chat input on the Ask page. `Esc` stops a stream (with focus in the input). `↑` in an empty input edits the last question.
- Citation chips are buttons with a descriptive `aria-label` ("Source: Stadtwerke invoice, November 2025").

## Tests

- **E2E:**
  - the empty-state suggestions come from seeded categories
  - ask → streamed answer → citation chip opens the preview
  - "Open as list" shows those documents
  - stop mid-stream keeps the partial answer
  - "Ask about this document" scopes to one document (the agent can't cite others)
- **Agent (FakeModel scripted):**
  - no results → the guidance message, with no fabricated citations
  - a numeric question → `query_facts` called and the table rendered
  - a masked restricted document → the notice is shown
  - the follow-up trailer is validated (and dropped if invalid)
- **Eval:** `qa.yaml` includes "find" questions (expected citation in the top 3) and number questions. Watch the 👎 rate in the usage page.

## Done when

Chat is one keystroke away from anywhere. The empty state suggests questions from the user's own data. Every answer has clickable sources, computed numbers and next steps. Failures tell the user what to do. Privacy is visible.
